# STEM CV Object Schema

This document describes the object layer generated by `scripts/stem_cv_curator.py`.

## Output file

```text
data/stem_cv_objects.json
```

## Top-level structure

```json
{
  "schema": "stem-cv-curator/v0.1",
  "run": {},
  "repositories": [],
  "projects": [],
  "claims": [],
  "sections": [],
  "render_targets": []
}
```

The standalone STEM presence scorer in `scripts/stem_presence.py` can be used to add or audit a `stem_presence` metric for papers, README files, status files, and other extracted public surfaces.

## Run object

```json
{
  "run_time": "2026-05-26 00:00:00 UTC",
  "trigger": "local",
  "scanned_repositories": 19,
  "active_project_objects": 19
}
```

Purpose: record how and when the curator generated the object layer.

## RepositoryObject

```json
{
  "repo_full_name": "owner/repo",
  "repo_name": "repo",
  "owner": "owner",
  "url": "https://github.com/owner/repo",
  "visibility": "public",
  "default_branch": "main",
  "archived": false,
  "active_status": "active",
  "last_observed_at": "2026-05-26 00:00:00 UTC",
  "topics": [],
  "detected_domains": ["machine_learning"]
}
```

Purpose: represent the GitHub repository as a CV-curation source.

## RepoSurfaceObject

```json
{
  "repo_full_name": "owner/repo",
  "source_path": "README.md",
  "source_type": "README",
  "available": true,
  "heading": "Project title",
  "status_line": "Active methods scaffold",
  "summary_text": "Short source-derived summary.",
  "retrieval_time": "2026-05-26 00:00:00 UTC",
  "note": null
}
```

Purpose: represent a README/status/roadmap/reproducibility surface checked during the scan.

## ProjectObject

```json
{
  "project_id": "example-ml-project",
  "title": "Example ML project",
  "repository": {},
  "maturity": "active_scaffold",
  "cv_section": "machine_learning",
  "public_summary": "Public machine-learning workspace for reproducible modeling.",
  "near_term_needs": "Add model card and benchmark target.",
  "source_surfaces": [],
  "keywords": ["machine_learning"],
  "include_in_cv": true,
  "include_in_resume": true,
  "display_priority": 100,
  "curated": true
}
```

Purpose: convert repository evidence into a CV-ready project object.

## StemPresenceScore

```json
{
  "score": 76,
  "drift_score": 24,
  "band": "core_stem",
  "rationale": "core_stem score 76/100 based on domain terms=8, method terms=6, reproducibility terms=4, progress terms=3.",
  "matched_domain_terms": ["machine learning", "dataset"],
  "matched_method_terms": ["validation", "benchmark"],
  "matched_reproducibility_terms": ["code", "workflow"],
  "matched_progress_terms": ["manuscript", "results"],
  "matched_drift_terms": []
}
```

Purpose: provide a transparent metric for STEM presence and drift from core STEM progress. `score` runs from 0 to 100. `drift_score` is `100 - score`. The current implementation is available as a reusable object and CLI in `scripts/stem_presence.py`.

## ClaimObject

```json
{
  "claim_id": "claim-example-ml-project",
  "project_id": "example-ml-project",
  "claim_text": "Public machine-learning workspace for reproducible modeling.",
  "claim_strength": "source_supported",
  "evidence_paths": ["README.md", "PROJECT_STATUS.md"],
  "public_safe": true,
  "cv_allowed": true,
  "resume_allowed": true,
  "needs_review": false
}
```

Purpose: separate what the CV says from what the repositories actually support.

## CVSectionObject

```json
{
  "section_id": "machine_learning",
  "title": "Machine Learning and Reproducible Research Tools",
  "projects": ["example-ml-project"]
}
```

Purpose: group projects for rendering.

## RenderTargetObject

```json
{
  "target_id": "academic_cv_public",
  "output_type": "academic_cv",
  "included_sections": [
    "publications",
    "machine_learning",
    "public_health",
    "biomedical_data",
    "methods",
    "archive_history",
    "intake"
  ]
}
```

Purpose: declare which sections are allowed in each output.

## Claim strengths

| Strength | Meaning |
|---|---|
| `source_supported` | README/status/roadmap files support the claim |
| `repo_supported` | Repository exists, but public status surfaces are weak or absent |
| `self_reported` | Claim comes from curated manifest text and requires review |
| `do_not_claim` | Claim should not be rendered |

## Maturity values

| Maturity | Use |
|---|---|
| `submitted` | Manuscript or article is submitted / under review |
| `publication_ready` | Print-ready or publication-ready object |
| `active_manuscript` | Active manuscript preparation |
| `active_scaffold` | Active repository with clear project direction |
| `early_stage` | Early method/topic development |
| `validation_gated` | Requires verification before strong claims |
| `intake` | Discovered repo needing curation |

## STEM presence bands

| Band | Score range | Use |
|---|---:|---|
| `core_stem` | 75-100 | Strongly aligned with STEM evidence, methods, reproducibility, and progress |
| `stem_adjacent` | 55-74 | Clear STEM connection but not fully documented as a core STEM output |
| `mixed_or_transitional` | 35-54 | Partial STEM evidence or immature intake-stage documentation |
| `low_stem_presence` | 0-34 | Weak STEM evidence or high drift from core STEM progress |

## CV sections

| Section ID | Rendered title |
|---|---|
| `publications` | Submitted and Publication-Oriented Work |
| `machine_learning` | Machine Learning and Reproducible Research Tools |
| `public_health` | Public Health, Infrastructure, and Environmental Evidence |
| `biomedical_data` | Biomedical Data and Signal/Imaging Methods |
| `methods` | Computational Methods and Safety Evaluation |
| `archive_history` | Archive and Public-History Indexing |
| `intake` | Discovered Repository Intake |
