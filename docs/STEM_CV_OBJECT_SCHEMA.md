# STEM CV Object Schema

This document describes the object layer generated by the public CV curator and its maturity-policy wrapper.

## Output file

```text
data/stem_cv_objects.json
```

This file is ephemeral build output, not a versioned portfolio source of truth. It is regenerated by `scripts/run_stem_cv_curator.py` before object-contract validation and is ignored by Git to prevent stale local snapshots from being committed. Durable project state belongs in `data/pipeline_repos.json` and the bounded public repository surfaces referenced by that manifest.

## Top-level structure

```json
{
  "schema": "stem-cv-curator/v0.3",
  "run": {},
  "repositories": [],
  "projects": [],
  "claims": [],
  "sections": [],
  "render_targets": [],
  "blocked_release_records": []
}
```

The standalone STEM presence scorer in `scripts/stem_presence.py` can be used to add or audit a `stem_presence` metric for papers, README files, status files, and other extracted public surfaces.

## Run object

```json
{
  "run_time": "2026-08-21 00:00:00 UTC",
  "trigger": "local",
  "scanned_repositories": 10,
  "active_project_objects": 10
}
```

Purpose: record how and when the curator generated the object layer.

## RepositoryObject

```json
{
  "repo_full_name": "owner/repo",
  "repo_name": "repo",
  "owner": "owner",
  "url": "https://github.com/owner/repo",
  "visibility": "public",
  "default_branch": "main",
  "archived": false,
  "active_status": "active",
  "last_observed_at": "2026-08-21 00:00:00 UTC",
  "topics": [],
  "detected_domains": ["biomedical_data"]
}
```

Purpose: represent the GitHub repository as a CV-curation source. Public rendering requires visibility to be independently verified before build completion.

## ProjectObject

```json
{
  "project_id": "cart-trace",
  "title": "Longitudinal CAR T-cell care-trajectory reconstruction",
  "repository": {},
  "maturity": "synthetic_freeze",
  "cv_section": "biomedical_data",
  "public_summary": "Synthetic-first translational health data-science framework.",
  "near_term_needs": "Preserve the frozen capstone and separately govern extensions.",
  "source_surfaces": [],
  "keywords": ["biomedical_data"],
  "include_in_cv": true,
  "include_in_resume": true,
  "display_priority": 0,
  "curated": true,
  "public_release": "public"
}
```

Purpose: convert repository evidence into a CV-ready project object while retaining a bounded research-maturity state.

## ClaimObject

Claims remain separated from repository state and include evidence paths plus release flags. A mature repository state does not, by itself, authorize clinical, causal, operational, or otherwise unsupported claims.

## Maturity values

The object contract accepts the following controlled vocabulary. The evidence-stage values are produced by `scripts/maturity_policy.py`; legacy values remain accepted for backward compatibility with existing generated objects.

| Maturity | Use |
|---|---|
| `synthetic_freeze` | Public synthetic research package is frozen and internally validated within its stated synthetic boundary |
| `pre_submission` | Manuscript is undergoing pre-submission cleanup, citation/model parity, or blinded-package review |
| `benchmark_freeze_pending` | Executable benchmark pathway exists but comparative evidence freeze is not yet complete |
| `pre_analysis` | Protocol/scaffold exists before validated empirical analysis |
| `source_validation` | Study is in source extraction, source validation, variable mapping, or reproducibility preparation |
| `active_research` | Active bounded research with defined scope but without a more specific maturity state above |
| `submitted` | Manuscript or article is submitted / under review; retained for backward compatibility |
| `publication_ready` | Publication-ready object; retained for backward compatibility |
| `active_manuscript` | Active manuscript preparation; retained for backward compatibility |
| `active_scaffold` | Active repository with clear project direction; retained for backward compatibility |
| `early_stage` | Early method/topic development; retained for backward compatibility |
| `validation_gated` | Requires verification before strong claims; retained for backward compatibility |
| `intake` | Discovered repository needing curation |

Unknown or missing maturity values fail the generated-object contract.

## STEM presence bands

| Band | Score range | Use |
|---|---:|---|
| `core_stem` | 75-100 | Strongly aligned with STEM evidence, methods, reproducibility, and progress |
| `stem_adjacent` | 55-74 | Clear STEM connection but not fully documented as a core STEM output |
| `mixed_or_transitional` | 35-54 | Partial STEM evidence or immature intake-stage documentation |
| `low_stem_presence` | 0-34 | Weak STEM evidence or high drift from core STEM progress |

## CV sections

| Section ID | Rendered title |
|---|---|
| `publications` | Submitted and Publication-Oriented Work |
| `machine_learning` | Machine Learning and Reproducible Research Tools |
| `public_health` | Public Health, Infrastructure, and Environmental Evidence |
| `biomedical_data` | Biomedical Data and Signal/Imaging Methods |
| `methods` | Computational Methods and Validation |
| `archive_history` | Archive and Public-History Indexing |
| `intake` | Discovered Repository Intake |
